## 📖 Overview

This directory contains the canonical Single Source of Truth (SSOT) documents for the CIS 531/731 course structure. It holds the core academic contracts, including the master syllabus, chronological schedule, environment setup requirements, and the explicit taxonomy governing the term project. All Canvas pages in the "Syllabus & Policies" module are generated directly from the Markdown files housed here.

> **⚠️ Sub-Directory Routing Notice**
> This directory serves a specific operational function. Ensure that artifacts committed here are strictly syllabus-level policies or structural guides. Grading rubrics specific to individual assignments belong in the `assignments/` directory.

<hr>

## 🗂️ Directory Structure

| Subdirectory / File | Description |
| :--- | :--- |
| `01_course_syllabus.md` | The master course syllabus, including grading schema, drop policies, and academic expectations. |
| `02_course_schedule.md` | The week-by-week chronological calendar of modules, lectures, and due dates. |
| `03_environment_runbook.md` | The "Keep Flying" protocol: Docker and VS Code DevContainer setup instructions required for all Machine Problems (MPs). |
| `04_term_project_guidelines.md` | The structural grading and milestone requirements for the capstone data science project. |
| `05_term_project_taxonomy.md` | The 3x5x5 Data Cube defining approved analytical categories, media types, and OSEMN stages. |
| `06_term_project_sourcing_guide.md` | The Tier 1-3 rubric for data source selection and the required Artifact-First Obtain/Scrub evidence. |
| `README.md` | This file. |

<hr>

## 🦅 Standard Operating Procedures (SOPs)

All personnel interacting with this directory must adhere to the following protocols:

* **Protocol 1 (SSOT Paramountcy):** Do not update policies directly in Canvas HTML. The Markdown files in this directory must be updated first, and the HTML mirrored from them.
* **Protocol 2 (Strict Numbering):** Files in this directory use sequential numbering (`01_`, `02_`) to enforce pedagogical reading order. Do not break the prefix sequence when adding new structural documents.
