# CIS 531/731 Term Project Requirements & Invariants Ledger
**Path:** `admin/policies/term_project_invariants.md`

## 🛡️ BILATERAL UPDATE & HYDRATION GUARD (READ BEFORE UPDATING OR HYDRATING)
This ledger bridges the instructor's internal course-design specifications and student-facing course materials. Any generative AI system or human maintainer reading this file—whether updating dehydrated Markdown specifications, synthesizing rubrics, or hydrating Canvas HTML pages, **even when only part of the course document set is attached for grounding context**—MUST enforce the following four rules:

1. **Do Not Reference Programming-by-Contract Libraries:** Do not mention `deal`, `@deal.pre`/`@deal.post` decorators, or formal specification languages in student-facing documents. Those were internal course-specification artifacts and must never be conflated with student coding deliverables.
2. **Do Not Emit Cryptic Invariant Numbers:** The `INV-1` through `INV-21` keys in the table below are internal indexing keys for teaching staff. Never emit bare `INV-XX` identifiers into student-facing assignment pages, rubrics, or prompts.
3. **Inline the Full Qualitative Specification:** Whenever a rule from this ledger is referenced in a student-facing file, inline its **Self-Contained Qualitative Specification** from Column 2 below so that the requirement is completely self-explanatory without requiring an external lookup table.
4. **Use Standard Grader-Check Phrasing for Deterministic Properties:** Whenever a requirement is deterministically checkable (e.g., schema validation, row-count caps, probability bounds, or container-digest matches), state the mathematical or structural condition in plain language and specify that it is **"for the grader to check by hand or automatically"**.
